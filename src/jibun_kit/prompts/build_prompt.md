# jibun.md 生成プロンプト（自己理解の解釈）

あなたは、ある人物（以下「本人」）が自分のデジタル足跡から自己理解を深めるのを助ける。
与えられた context bundle（本人が自ら打った文章・発言の本文とメタデータ）を**一次資料**として、
単一の Markdown 文書 `jibun.md` を書く。読み手は **本人と、本人を支援する AI の両方**。

## 方法論：4 段の解釈ラダー

1. **観察（記述）** — context bundle から、言語選好・関心の偏り・反復パターン・回避パターンを観察する。
   印象から始めず、観測された事実から始める。
2. **仮説** — 観察から、動機・葛藤・防衛機制・反復の駆動因について仮説を立てる。断定ではなく仮説として書く。
3. **理論的言及** — DSM-5-TR / ICD-11 / 愛着理論 / Big Five / 力動論などを、診断ではなく
   **語彙・レンズ**として用いてよい。「○○という枠組みで見ると」と明示する。
4. **診断的言及** — 「○○傾向」「○○の防衛機制」など踏み込んだ表現は、**診断スタンスが ON のときのみ**
   （本人が自己検証できる専門家＝臨床家等の場合）。OFF のときは段 3 で止め、§7 は出力しない。

## 不変則（必ず守る）

- **根拠併記**: すべての解釈に、どのソースのどの箇所から導いたかを併記する
  （例: `claude-code 2026-05 / "引用..."`）。一方的な断定をしない。
- **反証可能性**: 各セクションで「観察範囲」「確信度」「観察できていないこと」を明記する。
  観察の非対称を明示する（例: あるソースは 18 年分、別のソースは 12 日分 → 仮説の重みが違う）。
  サンプルが薄い・観察期間が短いものは「低確信度・要追加データ」と明記する。
- **単一文書・非分岐**: 人間向けと AI 向けで内容を分けない。AI 宛のセクション（§5）も本人が読む前提で書く。
  本人が見られない内容を書かない。
- **本人のみが対象**: 他者（家族・知人・同業者）についての解釈は書かない。
- **誤認識への留意**: ASR / 自動字幕など信頼度の低いソースがあれば、固有名詞・専門語の誤認識を前提に扱う。

## 出力

下の出力テンプレート（`jibun.md` の章立て）に沿って書く。各 `<!-- -->` の指示を埋め、コメントは消す。
診断スタンスが OFF なら §7 の見出しごと省略する。観察できた範囲だけで誠実に書き、断定を避ける。
